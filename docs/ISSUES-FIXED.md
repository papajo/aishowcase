# Issues Fixed — 2026-07-25

## 1. Raw CSS leaking into HTML-converted blog posts

**Problem:** Dropping an Odysseus HTML report into `content/incoming/` produced a blog post with 500+ lines of CSS at the top.

**Root cause:** `markdownify`'s `strip` parameter removes tags but keeps their text content. The `<style>` block's CSS was converted to raw text.

**Fix:** Replaced `strip=["script", "style", ...]` with `re.sub()` that removes `<style>`, `<script>`, `<nav>`, `<footer>`, `<header>` blocks entirely (content + tags) before conversion.

**File:** `scripts/publish_incoming.py` line 87

---

## 2. Odysseus UI artifacts in published posts

**Problem:** Published posts contained "Export ▾", "Save as PDF", "Discuss", "Generated by Odysseus Deep Research", research metadata ("598.4s Duration", "searxng Search"), and JavaScript code.

**Root cause:** Odysseus report HTML includes toolbar buttons, footer text, and inline JavaScript that survive markdownify conversion.

**Fix:** Added `_clean_odysseus_artifacts()` function that strips known Odysseus UI patterns after markdown conversion. Applied to the HTML conversion path.

**File:** `scripts/publish_incoming.py` lines 75-113

---

## 3. Odysseus login broken over HTTP (Secure cookie flag)

**Problem:** Browser login appeared to succeed but session didn't persist. Subsequent requests returned 401/403. PDF export produced 0-byte files.

**Root cause:** Odysseus set session cookie with `Secure` flag, but runs on plain HTTP (`http://127.0.0.1:7001`). Browsers refuse to store `Secure` cookies over non-HTTPS connections.

**Fix:** Changed `SECURE_COOKIES=true` to `SECURE_COOKIES=false` in `/Users/padoshi/Projects/Odysseus/.env`.

**Verified:** `Set-Cookie` header now shows `odysseus_session=...; HttpOnly; Max-Age=604800; Path=/; SameSite=lax` (no `Secure` flag).

**File:** `/Users/padoshi/Projects/Odysseus/.env` line 85

## 4. PDF export producing 0-byte files

**Problem:** "Save as PDF" in original format produced empty PDF files. Simple format worked.

**Root cause:** Two issues combined:
1. `Secure` cookie (fixed in #3) caused authenticated resources to fail during print
2. Complex CSS (aurora gradients, animations, fixed positioning) broke browser print renderer in "original format"

**Fix:**
1. Cookie fix (#3) ensures resources load during print
2. Enhanced `@media print` CSS in Odysseus to:
   - Hide `body::before`/`body::after` (aurora gradients, film grain)
   - Strip animations and transitions
   - Reset fixed positioning to static
   - Prevent page breaks inside code/tables/blockquotes
   - Set proper page margins

**File:** `/Users/padoshi/Projects/Odysseus/src/visual_report.py` lines 827-847

## 5. localhost URLs leaking into post titles

**Problem:** Posts converted from Odysseus HTML/PDF had `http://localhost:7001/api/research/report/rp-xxxxx` in the title.

**Root cause:** Odysseus report HTML embeds localhost URLs in `<title>` and heading tags. `extract_title_from_html()` grabbed them verbatim.

**Fix:** Added `_clean_title()` function that strips URLs (`http://...`, `https://...`, `localhost:port/...`) and Odysseus research metadata from titles. Applied to HTML conversion, PDF conversion, and the first heading in markdown body.

**File:** `scripts/publish_incoming.py` lines 62-80, 128-135, 174

## 6. start-macos.sh fails when Docker is running

**Problem:** Running `./start-macos.sh` while Docker Odysseus is up shows generic "Port already in use" error.

**Root cause:** Script checks if port is taken but doesn't distinguish between Docker and native processes.

**Fix:** Added Docker detection — if Docker is using the port, shows a specific message suggesting `docker compose down` or noting Docker is already running.
